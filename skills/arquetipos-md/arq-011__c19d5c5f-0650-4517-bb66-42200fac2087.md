Spring Framework is the actual framework and
infrastructure provided that Spring Boot leverages from.

In order to understand Spring Framework, at its core, provides:

Dependency Injection (IoC Container)
Bean lifecycle management
Transaction management
Web development through Spring MVC
Security integrations
Data access abstraction

Also, instead of developers manually creating and managing objects,
Spring Framework manages them as beans inside the ApplicationContext
(imagine it like a container where all these beans live) and scans them
for configuration purposes or to inject on other classes.

And it’s awesome because this involves great modules such as: Spring
AOP, Spring MVC, Spring Data, Spring Security, Spring Cloud, etc...

But... Let me tell you what’s the hell embedded into this.

12Application Context@mauricioperez

One of the biggest risks in modern Java backend development
is  becoming  a  “Spring  Boot-only  developer”  without  truly
understanding Spring Framework underneath.

The  consequences  of  only  using  Spring  Boot  are  some  of  the
following:

Overdependence on auto-configuration
Weak understanding of the ApplicationContext
Difficulty debbuging startup failures
Treating Spring Boot as “magic”
Limited customization capabilities
Poor understanding of bean lifecycle and scopes

... and some more.

Spring Boot is an incredible productivity layer, but Spring
Framework is the beast of this whole ecosystem.
